# Документация проекта url-shortener

Учебный проект сокращателя ссылок на Go. Цель — не «ещё один сервис в портфолио», а
осознанная отработка различия между **синхронной записью на горячем пути** и
**асинхронным конвейером на конкурентных примитивах Go**. Проект построен в два этапа,
и весь смысл — почувствовать боль первого этапа, чтобы во втором её осознанно убрать.

## Философия двух этапов

| | Этап 1 — синхронный скелет | Этап 2 — конкурентность |
|---|---|---|
| Счётчик кликов | синхронный `UPDATE ... click_count + 1` прямо в обработчике редиректа | событие летит в буферизованный канал, редирект отвечает сразу |
| Запись в БД | на горячем пути, блокирует ответ | вынесена в worker pool, батчевый флаш |
| Назначение | намеренно «плохо для прода» — создать конкретную боль | рефакторинг этой боли, замер p99 до/после |
| Транспорт | только HTTP | только HTTP |
| Новое | chi, pgx, Redis, миграции, тесты | каналы, worker pool, Kafka, Prometheus, rate limit, sweeper |

> Главная цифра на собеседовании: p50/p99 редиректа **до** и **после** рефакторинга.
> Без этого «до/после» урок не закрепляется.

## С чего начать

1. Прочитай [architecture.md](./architecture.md) — общая картина и почему слои разделены.
2. Посмотри [project-structure.md](./project-structure.md) — как разложить код и в каком порядке писать.
3. Делай [stage-1.md](./stage-1.md) от начала до конца, не заглядывая в Этап 2.
4. Замерь p99 редиректа под нагрузкой ([operations.md](./operations.md)).
5. Делай [stage-2.md](./stage-2.md), замерь p99 снова, положи цифры рядом.

## Принятые инженерные решения (кратко)

Там, где README оставляет выбор, документация делает рекомендацию и обосновывает её.
Полные обоснования — в соответствующих документах.

| Вопрос | Рекомендация | Где обосновано |
|---|---|---|
| 301 или 302 для редиректа | **302** (Found) | [api.md](./api.md), [architecture.md](./architecture.md) |
| goose или golang-migrate | **goose** | [data-model.md](./data-model.md) |
| Kafka или NATS | **Kafka** (учебная ценность) | [architecture.md](./architecture.md) |
| Политика backpressure | **drop + метрика** на горячем пути | [architecture.md](./architecture.md) |
| Семантика доставки в Kafka | **fire-and-forget** для счётчика, at-least-once опционально для аналитики | [architecture.md](./architecture.md) |
| Порядок написания слоёв | **repository → service → handler** | [project-structure.md](./project-structure.md) |
